# Карта проекта alusan

Обновлять этот файл при структурных изменениях (новые роуты, новые общие компоненты, смена источника данных). Дата последнего обновления: 2026-09-30.

## Стек

- **Next.js 16** (App Router, Turbopack), **React 19**, **TypeScript**
- **Tailwind v4** — токены цвета через CSS-переменные в `app/globals.css` (`@theme inline`)
- Шрифты через `next/font/google` (`app/layout.tsx`): **Manrope** — единственный шрифт сайта (и заголовки, и текст, разница только в начертании/размере), **JetBrains Mono** — мелкие моно-лейблы (эйбрау, спецификации)
- **Postgres 16 + Prisma 6** — см. раздел "Бэкенд / БД" ниже. Локально БД поднимается через Docker.
- **pnpm**. `render.yaml` в корне — это **не** прод-деплой, а разовый способ показать превью заказчику. Реальная площадка для деплоя (и БД) пока не определена.
- UI-примитивы из shadcn (`components/ui/`), иконки — `lucide-react`

## Структура каталогов

```
app/                 роуты (App Router, каждая папка = URL-сегмент)
components/          общие переиспользуемые компоненты
components/ui/       shadcn-примитивы (button и т.п.)
lib/db.ts            синглтон Prisma-клиента
lib/products.ts      data-access для каталога (категории/товары) — обёртка над Prisma
lib/articles.ts      data-access для статей — обёртка над Prisma
lib/utils.ts         cn() — склейка classNames (clsx + tailwind-merge)
prisma/schema.prisma схема БД (Product, Category, Article, Lead, AdminUser)
prisma/seed.ts       сидинг (npm run db:seed) — наполняет БД из seed-data.ts/seed-articles.ts
public/              статика: brand/ (логотип), favicon.ico/svg, apple-touch-icon.png, icon-192/512.png, hero-ladders.png. Мусора от v0 (placeholder-*, старые иконки) больше нет — вычистили.
workflows/           материалы заказчика + наши план/карта (см. .gitignore — бинарники не коммитим)
```

## Общие компоненты (`components/`)

| Компонент        | Зачем                                                                                                                                                                                                                                                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Container`      | Центрирующая обёртка контента (`mx-auto px-5 lg:px-10` + ширина). `width="default"` (1440px, по умолчанию) или `width="narrow"` (1200px, у `/cooperation` и `/documents`). Используется **везде**, включая шапку/футер и большую шапку главной — это единственное место, где живут отступы контейнера, руками их больше нигде не пишем. |
| `SiteHeader`     | Шапка для всех подстраниц (light/dark вариант, ссылки, кнопка "назад"). Главная страница использует свою отдельную шапку (fixed + blur + бургер-меню — реально другое поведение), но оба варианта строятся на одном `Container`, поэтому высота и положение логотипа совпадают пиксель-в-пиксель.                                       |
| `SiteFooter`     | Единый футер, везде одинаковый, тоже на `Container`                                                                                                                                                                                                                                                                                     |
| `SiteBrand`      | Логотип: `dark` (по умолчанию false) переключает `public/brand/logo.svg` (цветной, для светлых шапок) на `public/brand/logo-white.svg` (белый, для тёмных шапок/фото-фонов и футера)                                                                                                                                                    |
| `ProductCard`    | Карточка товара, 3 варианта отображения: `teaser` (главная), `catalog` (каталог), `category` (страница категории)                                                                                                                                                                                                                       |
| `PillFilter`     | Кнопки-фильтры (категории в каталоге, вкладки в документах)                                                                                                                                                                                                                                                                             |
| `LeadForm`       | Форма заявки (используется на главной и `/contacts`), полностью на клиенте, ничего никуда не отправляет — `useState` + `preventDefault`. `tone`: `default` / `onLime` / `onBlue` — под фон секции, на которой стоит форма.                                                                                                              |
| `SectionEyebrow` | Маленькая моно-надпись над заголовками секций                                                                                                                                                                                                                                                                                           |

### Шкала заголовков

Начертание/трекинг/интерлиньяж h1/h2/h3 заданы один раз в базовом правиле `app/globals.css` (`@layer base`) — руками на каждой странице их больше не выставляем. Размер — два готовых класса там же:

- `.heading-1` — заголовок страницы (`text-6xl sm:text-7xl`), используют `/catalog`, `/catalog/[category]`, `/contacts`, `/cooperation`, `/documents`, `/technology`
- `.heading-2` — заголовок секции (`text-5xl sm:text-6xl`), используют секции на `/` и `/about`

Главные hero-заголовки (`/` и `/about`) — исключение, у них свой `clamp()`-размер, это осознанно (единственный настоящий "hero" на сайте).

## Бэкенд / БД

Данные каталога и статей больше не хардкод — реальный Postgres через Prisma.

**Поднять локально:**

```
docker compose up -d          # Postgres в контейнере, см. docker-compose.yml
npx prisma migrate dev        # применить схему (prisma/schema.prisma)
pnpm db:seed                  # наполнить категориями/товарами/статьями
pnpm db:studio                # опционально — GUI для БД (Prisma Studio)
```

`.env` — `DATABASE_URL`, не коммитится (см. `.env.example` для формата). Локальный Postgres поднят в докере на порту **5434**, не 5432 — на машине уже висел нативный Windows-сервис Postgres на 5432, конфликтовали.

**Схема (`prisma/schema.prisma`):** `Category`, `Product` (связан с `Category`), `Article` (тело — Markdown, статус `draft`/`published`), `Lead`, `AdminUser`. Последние два пока не используются кодом — таблицы под `/contacts`-форму и будущий логин админки (фаза 3).

**Data-access слой:**

- `lib/products.ts` — `getCategories`, `getCategoryBySlug`, `getAllProducts`, `getProductsByCategorySlug`, `getProductsByNames`
- `lib/articles.ts` — `getPublishedArticles`, `getPublishedArticleSlugs`, `getArticleBySlug`

**Сидинг (`prisma/seed.ts`):** данные каталога — из `prisma/seed-data.ts` (перенесены из бывшего `lib/data/products.ts`, файл удалён). Статьи — из `prisma/seed-articles.ts`, это текст из `наполнение ai.docx` **как есть**, но с уже убранными названиями моделей конкурента (`BT Pro`, `HH1` — см. план, пункт про alumet.ru). Финальный редакторский проход (тон, бренд-нейминг после решения) ещё предстоит — статьи уже `published`, чтобы видеть рабочий раздел, а не заглушку.

**Важно:** товары по-прежнему отображаются абстрактной "лестницей"-градиентом (`ProductCard`, поле `tone`), реальных фото товаров в проекте нет.

## Дизайн-токены (`app/globals.css`)

Под `@theme inline` объявлены `--color-brand-*`, переиспользуются в Tailwind как `bg-brand-ink`, `text-brand-muted` и т.д. Палитра — реальные цвета логотипа: `--brand-blue` (`#044b8a`, основной, используется в тексте/кнопках/акцентах) и `--brand-blue-dark` (`#033a6b`, приглушённый — для больших сплошных плашек-секций, чистый `--brand-blue` на весь экран оказался слишком ярким). `--brand-lime` (`#9bc538`, зелёный) — **только акцент**: мелкие лейблы, иконки, hover, маленькие кнопки, никогда не фон большого блока (на светлом фоне ещё и `--brand-lime-ink`/`--brand-muted` — затемнённые варианты для читаемости мелкого текста). `--brand-surface-1/2/3` — тёмные навy-тона для шапки/hero/футера.

## Известные ограничения (что не работает по-настоящему)

- Формы (`LeadForm`, форма на `/contacts`) — фейковые, только меняют текст кнопки; таблица `Lead` в БД есть, но форма в неё ничего не пишет (это фаза 3 — server action + вызов из формы)
- `/admin` — статичная витрина, нет авторизации, нет связи с БД; таблица `AdminUser` есть, логина нет
- Нет реальных фото товаров и производства (используется общий `hero-ladders.png` + абстрактная градиентная "капсула" на карточках)
- Статьи опубликованы с текстом из наполнения без финального редакторского прохода (см. раздел "Бэкенд / БД")

## Бенчмарк конкурента (alumet.ru)

Смотрели структуру для ориентира по IA (не копируем 1-в-1, но полезно знать):

- Категории каталога совпадают с нашими один в один: Лестницы/Стремянки/Шарнирные лестницы/Вышки-туры/Подмости/Аксессуары
- `/articles/` — статьи отдельным пунктом меню, не вложены никуда → берём такое же название и место
- `/company/contacts/` — контакты у них вложены под "О компании", у нас `/contacts` отдельный пункт — оставляем как есть, это не хуже
- У них нет отдельной страницы про технологию/материалы — у нас `/technology` есть, это наше отличие, не убираем
- Часть наполнения заказчика (3 из 8 статей, названия моделей `BT Pro`/`HH1`) текстуально совпадает с alumet.ru — см. открытые вопросы в `план-доработки.md`
